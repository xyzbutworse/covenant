# Attestcoin integration

COVENANT integrates the **current native query-verifier architecture** — not the deprecated
callback/prover flow. Everything below reflects the installed pins and was checked against the
live environment during development (`evidence/network-probe.json`).

## Pins

- native BlockProver precompile: `0x0000000000000000000000000000000000000fD2`
- ChainInfo precompile: `0x0000000000000000000000000000000000000fD3`
- proof SDK: `@gluwa/usc-sdk@0.18.0` (registry latest)
- decoder contracts: `@gluwa/usc-contracts@0.1.2`
- official examples source of truth:
  [`gluwa/attestcoin-protocol-examples`](https://github.com/gluwa/attestcoin-protocol-examples)

## Verification surface

`CovenantFacility.submitEvidence` receives chainKey, block height, encoded transaction bytes,
Merkle root + sibling path, and continuity material. The contract then calls:

```solidity
VERIFIER.verifyAndEmit(chainKey, height, encodedTransaction, merkleProof, continuityProof) → bool
```

This selector matches the canonical ABI shipped in
`usc-sdk/dist/block-prover/block_prover.json` byte-for-byte
(`verifyAndEmit(uint64,uint64,bytes,(bytes32,(bytes32,bool)[]),(bytes32,bytes32[]))`).
`verifyAndEmit` reverts on verification failure; COVENANT additionally treats a `false` return as
`ProofVerificationFailed`. No economic field is read unless this succeeds.

The replay identity is derived on-chain from proof-covered data:
`keccak256(chainKey ‖ blockHeight ‖ calculateTxIndex(merkleProof))`, where `calculateTxIndex`
recovers the transaction index by walking the sibling path. It is consumed once globally after all
semantic checks pass.

## Decoder

`EvmV1Decoder@0.1.2` decodes the `(uint8, bytes[])` USC v1 encoding that the SDK's
`encoding.abiEncode` produces (and therefore what the proof builder returns as `txBytes`):

1. `getTransactionType` + `isValidTransactionType` — reject anything outside types 0–4 before decoding;
2. `decodeReceiptFields` — receipt chunk (index 2 for types 0–2, 3 for types 3–4);
3. explicit success gate: `receiptStatus != 1 → SourceTransactionFailed`. Inclusion alone never satisfies anything;
4. `getLogsByEventSignature(Transfer)` filtered to the approved emitter; indexed topics must be exactly payer/recipient; data exactly one 32-byte amount.

Unit-test fixtures are generated by `scripts/generate-fixtures.cjs` using the official SDK encoder
and `KeccakMerkleTree`, so contract tests consume authentic USC v1 artifacts rather than
hand-built approximations.

## ChainInfo at 0x…0FD3

Used for two purposes:

1. **Discovery** (`worker:discover`): lists supported source chains and attestation frontiers.
   Unsupported keys return `null`; the worker skips them explicitly.
2. **Freeze eligibility** (on-chain): `freezeExpiredCovenant` reads
   `get_latest_attestation_height_and_hash(chainKey)` and requires the frontier to have advanced to
   at least `endSourceBlock + freezeFrontierMarginSourceBlocks`. Selector compatibility with our
   Solidity interface was verified directly against the live precompile via raw `eth_call`
   (`0x809112da…`), recorded in `evidence/network-probe.json`.

## Worker timing

The worker follows the current official example pattern:

1. resolve the source transaction's block;
2. read the attestation frontier through ChainInfo;
3. wait until the block is attested *and ingested* by the proof builder
   (`ProofBuilder.waitUntilHeightAttested`);
4. request a fresh proof;
5. submit immediately — `worker:submit` rebuilds the proof by default right before broadcasting
   (`PROOF_SOURCE=fresh`); cached-file mode enforces a max artifact age because continuity
   material is fresh data, not a durable artifact.

## Local test doubles

Foundry tests etch behavior-faithful doubles at both precompile addresses
(`MockNativeQueryVerifier`, `MockChainInfo`) so unit tests exercise COVENANT's exact production
call surface. These are test-only contracts under `contracts/test/`; production sources contain no
mocks, and live integration code is never replaced by them.
